# NetMap · карта: базовые замеры текущей реализации

**Версия:** 0.63.0 · **ветка:** `arena/01a0da2c-netmap` · **дата:** 2026-09-25

Назначение: эталонная планка, с которой сравнивается файл макетов `map-variants.html`.
Все цифры получены замерами в песочнице (методика — §7), а не «на глаз».
Файл лежит в репозитории намеренно: артефакты вне репо не переживают откат снепшота.

---

## 0. Что замерялось и зачем

Задача — оценить текущее окно/карту по трём критериям: **удобство, скорость, визуал**.
Макеты не дошли до песочницы (см. §8), поэтому здесь зафиксирована вторая половина сравнения —
измеримая база текущей реализации. Замеры §2 сделаны на v0.62.2; на v0.63.0 изменился только
состав плавающих элементов (см. §3), метрики карточек те же.

## 1. Что представляет собой окно сейчас

Каркас (`App.tsx`), сверху вниз:

| Слой | Компонент | Что делает |
|---|---|---|
| 1 | `MenuBar` | HTML-меню File/View/Tools/Monitor/Help |
| 2 | `Toolbar` | поиск, фильтры, пресеты видов, горячие клавиши |
| 3 | `ToolsStrip` | draw.io-полоса: 17 кнопок в 5 группах + split-меню стратегий, сворачивается |
| 4 | `UpdateBanner` | плашка обновлений (появляется редко) |
| 5 | `NewSidebar` ← карта → `RightPanel` | 5 разделов слева · карта · инспектор/обзор справа |

Плавающие элементы **поверх** карты: `Controls` (зум), `MiniMap`, сетка 20 px,
`PathBanner` (top:10, центр), `VlanFilterBanner` (top:12, центр), `SubnetLegend` (top:12, центр),
`HiddenEdgesChip` (top:12, слева), `MultiSelectBar` (bottom:40, центр), пилюли-ориентиры хабов,
шевроны панелей `‹ ›` по краям. После v0.63.0 синего круга `LayoutFAB` в кадре больше нет.

### Карточки устройств (вид «modern», `ModernDeviceNode.tsx`)

- **Хаб** (роутер/свитч/патч-панель/сервер/облако): белая карточка 260–300 px, круглый
  градиентный аватар 52 px (или фавикон устройства), имя 14 px/700, модель · IP, пилюля
  Online/Offline, секция «Connected Devices» с чипами по типам оконечных.
- **Оконечное** (AP/камера/ПК/касса/принтер/замок): компактная карточка 180 px, аватар 32 px,
  имя 12 px, IP + точка статуса.
- **Маяк** (дальний зум): крупное имя, статус, плашка CORE для ядра, полоса счётчиков оконечных.

### Семантический зум (v0.57) — сильная сторона реализации

| Ступень | Порог | Что происходит |
|---|---|---|
| `near` | zoom ≥ 0.74 | полные карточки, чипы «Connected Devices» |
| `mid` | 0.39–0.74 | ужимает: листы без IP-строки, хабы без чипов |
| `far` | zoom < 0.31 | хабы → «маяки», оконечные **скрываются** с канваса в хаб |

Гистерезис ±0.04 не даёт «дребезга» на границе ступеней.

### Пороги производительности

- `onlyRenderVisibleElements` — рендерятся только узлы/рёбра во вьюпорте.
- `doc.devices.length > 150` → отключается `MiniMap` и упрощается роутинг рёбер
  (`edgeRouterVersion` замораживается).
- `memo` на всех типах узлов с компаратором по ссылкам/примитивам (`sameNodeProps`).

## 2. Скорость: измеренные цифры

### 2.1 DOM-вес карточек (рендер в статический HTML)

| Карточка | DOM-узлов | inline-style | HTML | Состав |
|---|---|---|---|---|
| Оконечное устройство | **24** | 17 | 4.2 KB | div:16 path:3 span:2 svg:1 |
| Хаб, обычный вид | **100** | 66 | 18.7 KB | div:87 rect:7 span:5 svg:1 |
| Хаб + «Connected Devices» | **160** | 96 | 23.9 KB | div:99 span:18 rect:12 line:7 svg:6 |
| Хаб, средний зум (`mid`) | **105** | 70 | 19.1 KB | — |
| Хаб-маяк (`far`) | **135** | 72 | 21.8 KB | — |

Что даёт семантический зум на одном хабе: `near` 160 → `mid` **105** (−34 % DOM).
Маяк `far` (135) сам по себе не легче — выигрыш в том, что Canvas убирает **все** оконечные карточки.

### 2.2 Проекция на реальные схемы

| Устройств | near (всё видно) | far (только хабы) |
|---|---|---|
| 50 | ~2 000 DOM | ~810 |
| 100 | ~4 000 DOM | ~1 620 |
| 200 | ~8 000 DOM | ~3 240 |
| 400 | ~16 100 DOM | ~6 480 |

### 2.3 Скрытый расход: невидимые портовые якоря

Каждая карточка рендерит `Handle`-ы React Flow на **каждый порт** (source + target),
плюс 8 запасных якорей по сторонам. Они невидимы (opacity 0), но занимают DOM и layout:

| Устройство | DOM всего | из них якорей | доля |
|---|---|---|---|
| Коммутатор, 24 порта | 98 | 56 | 57 % |
| Роутер, 8 портов | 51 | 24 | 47 % |
| Камера, 1 порт | 25 | 10 | 40 % |
| Устройство без портов | 20 | 8 | 40 % |

То есть **40–57 % DOM карты — невидимые абсолютно спозиционированные элементы**.
На схеме в 200 устройств это ~2 500–3 000 лишних узлов.

### 2.4 Бандл

| Чанк | Размер | gzip |
|---|---|---|
| `index` (приложение) | 862 KB (было 871 до v0.63.0) | 242 KB |
| `reactflow` | 327 KB | 105 KB |
| `dagre` | 89 KB | 31 KB |
| CSS | 20 KB | 4 KB |

Vite предупреждает про чанк > 800 KB. Код-сплиттинг сделан только для xterm/qrcode/dagre.

### 2.5 Архитектурные меры, которые уже есть

- `memo` + узкие селекторы (`useShallow`) — узел перерисовывается только по своим данным.
- `onlyRenderVisibleElements` — главный источник экономии на больших схемах.
- Семантический зум, отключение MiniMap и роутера рёбер после 150 устройств.
- Императивное обновление пилюль-ориентиров без ре-рендеров React.

## 3. Удобство: пути к частым действиям

| Действие | Путь сейчас | Оценка |
|---|---|---|
| Выбрать устройство | 1 клик по карточке → карточка выделяется, **сама открывается правая панель** | хорошо |
| Детальный вид устройства | двойной клик по карточке → Focus View (порты, связи, «Соединить») | хорошо |
| Соединить кабель | драг **с невидимой точки** 6×6 px на краю карточки → дроп на целевое устройство → диалог выбора портов (`PortPickerDialog`). Альтернатива: Focus View → клик по свободному порту | слабое место в начале, дальше удобно |
| Удалить кабель | режим «нож» (T) → клик по связи | хорошо |
| Добавить устройство | каталог в левой панели → перетаскивание на карту | нормально |
| Раскладка схемы | 4 кнопки на `ToolsStrip` + меню стратегий на шевроне (v0.63.0) | хорошо |
| Импорт/обнаружение/traceroute/Vault | 5 кнопок на `ToolsStrip` | хорошо |
| Экспорт PNG/SVG/JSON | 3 кнопки на `ToolsStrip` | хорошо |

Наблюдения:
- **Главный провал в удобстве — соединение кабелей на карте:** якоря портов невидимы, попасть
  в 6×6 px на дальнем зуме почти невозможно. Подсветка корректных целей во время драга
  (`netmap-connect-target`) есть, но начать драг негде найти.
- **Дублирование (исправлено в v0.63.0):** `LayoutFAB` (синий круг справа) повторял кнопки
  полосы. Удалён вместе с фан-меню и подсказкой «схема выглядит запутанно»; меню из 4 стратегий
  раскладки переехало на split-кнопку «Умная раскладка» (иконка = гибрид в один клик,
  шеврон = меню: гибрид / локации / VLAN / подсети).
- **Верхняя полоса перегружена:** 4 плавающих элемента в одной зоне (PathBanner,
  VlanFilterBanner, SubnetLegend, HiddenEdgesChip) — конфликтуют между собой и с содержимым карты.

## 4. Визуал

- Стиль: белые карточки, радиус 10–14 px, тонкая рамка `#E5E7EB`, мягкие тени
  (`0 2px 8px rgba(15,23,42,0.05)`), круглые градиентные аватары, цветные пилюли статуса.
- Палитра по типам: свитч `#0D9488`, роутер `#60a5fa`, патч-панель `#c084fc`, AP `#f59e0b`,
  камера `#f87171`, сервер `#94a3b8`, ПК `#a3a3a3`, облако `#38bdf8`.
- Статусы: Online `#22C55E` / Offline `#EF4444`, фон пилюль `#F0FDF4`/`#FEF2F2`.
- Сетка 20 px, цвет `#E5E7EB` (отключаемая).
- **Решение по слоям:** связи принудительно выше карточек (`z-index: 2000 !important`),
  то есть кабели рисуются **поверх** карточек. Группы — ниже карточек (`z-index: 0`).

Спорные места:
1. Все связи поверх всех карточек — на плотной схеме кабели «режут» текст на карточках.
2. Много мелкого текста: 10 px для IP/модели — на 1080p читается с трудом (особенно на `mid`).
3. До 10 плавающих элементов в одном кадре конкурируют за внимание с самой схемой.

## 5. Слабые места, ранжированные

1. **Невидимые порты при соединении** — страдает удобство, лечится без смены макета
   (видимые якоря при hover/на карточке, либо кнопка «Соединить» на карточке).
2. **40–57 % DOM — невидимые handle-ы** — резерв скорости: рендерить якоря только для
   занятых портов + 1 «свободный» якорь на сторону.
3. ~~Дублирование раскладки (FAB ↔ ToolsStrip)~~ — **закрыто в v0.63.0**.
4. **Перегруженная верхняя полоса** — 4 элемента в одной зоне.
5. **Связи поверх карточек** — визуальный шум на плотных схемах.
6. **Мелкий кегль** (10 px) на второстепенных строках карточек.

## 6. Критерии, по которым будет разбор макетов

| Критерий | Что смотрю | Как измерю |
|---|---|---|
| **Скорость** | число DOM-узлов на карточку/схему, слои прорисовки, есть ли виртуализация и ступени зума, сколько inline-стилей и анимаций | тот же стенд: SSR-рендер + подсчёт тегов/стилей, сравнение с таблицей §2 |
| **Удобство** | клики до частых действий (соединить, найти, разложить, экспорт), видимость портов, что дублируется, где конкурируют панели | таблица «действие → клики», сравнение с §3 |
| **Визуал** | иерархия (что первым читается), плотность, читаемость кегля ≥11 px, порядок слоёв (карточки/связи/легенды), воздух вокруг карты | разбор + проверка ключевых цветов на контраст WCAG |
| **Реализуемость** | можно ли внедрить в текущий стек (React Flow + zustand + DialogTheme), что переиспользуется, объём переделки | оценка по файлам: `Canvas.tsx` / `ModernDeviceNode.tsx` / `App.tsx`, влияние на релиз |

Итог будет в формате: по каждому варианту — сильные/слабые, затем **однозначная рекомендация**
(взять A / гибрид A+B / оставить текущий) с ценой внедрения в версиях.

## 7. Методика замеров (воспроизводимо)

Стенд вне репозитория (пересоздаётся по рецепту из `AGENT_CONTEXT.md` §6 п.6):
1. Копия `src/ModernDeviceNode.tsx` с подменённым импортом стора на фейковый (позволяет
   переключать `zoomBand`/`collapseEndpoints` между рендерами — в обычном SSR zustand v5
   отдаёт `getInitialState` и правки стейта не видны).
2. `esbuild` → CJS-бандл, `react-dom/server` → `renderToStaticMarkup`.
3. Подсчёт: число тегов `<tag`, число `style="`, байты HTML, отдельно — число
   `class="react-flow__handle`.

Runtime-проверки UI — jsdom-стенд (v0.63.0: 23/23 для полосы инструментов);
обязательные условия работы стенда — `IS_REACT_ACT_ENVIRONMENT`, `CustomEvent` из реалма jsdom,
подмена `requestAnimationFrame` (см. `AGENT_CONTEXT.md` §6 п.6).

Восстановление окружения: `npm ci --ignore-scripts`, затем
`./node_modules/.bin/tsc --noEmit && npm run build`.

## 8. Блокер по макетам

Файл `map-variants.html` **дважды не дошёл** до песочницы: каталога `/home/user/uploads/`
нет, поиск по всей файловой системе (включая скрытые каталоги) не находит ни `map-variant*`,
ни свежих файлов вне репозитория; в истории git файла тоже нет. Дело не в размере файла,
а в канале передачи вложений.

Рабочие обходные пути (пользователь выбрал первый):
1. **Вставить HTML прямо в чат текстом** — самый надёжный; если файл большой, можно частями.
2. **Дать публичную ссылку** (gist / pastebin / raw-ссылка) — скачаю сам.
3. **Положить файл в репозиторий** (например, `docs/map-variants.html` в ветке).
