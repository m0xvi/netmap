# Логика сцены: LOD, фасовка и правила расположения (v0.68)

Этот документ — спецификация того, **как карта решает, что и в каком виде
показывать**. Вся логика сведена в один чистый модуль `src/scenePlan.ts`
(«контракт сцены»); `Canvas.tsx` только отображает план. Раньше эвристики
«кого спрятать» жили в трёх местах и расходились между собой — это причина
«мёртвых» режимов и лишнего DOM.

## 1. Принципы

1. **Зум меняет детализацию, а не существование.** Каждое устройство
   представлено на каждой ступени: карточкой, маяком или счётчиком внутри
   хаба/пилюли. Ничто не «пропадает» — оно фасуется.
2. **Иерархия первична.** Ядро → дистрибуция → доступ → оконечные
   (`src/layers.ts: inferLayer`). Раскладка и фасовка уважают иерархию.
3. **Детерминизм.** План — чистая функция `(doc, zoomBand, collapseEndpoints,
   viewMode, linkVisible) → ScenePlan`: повторный расчёт даёт тот же результат,
   карта не «дрыгается» при зуме.
4. **Фасовка вместо скрытия.** Оконечное с ровно одним хабом уходит счётчиком
   в хаб; состав группы на обзоре уходит счётчиком в пилюлю; параллельные
   кабели агрегируются в пучок «×N».
5. **Производительность — правилом, а не заплаткой.** Дорогой DOM (портовые
   якоря, карточки оконечных, индивидуальные кабели) существует только там,
   где он виден пользователю.

## 2. Ступени зума (zoomBand)

| Ступень | Условие | Устройства | Группы | Связи |
|---|---|---|---|---|
| **near** | zoom ≥ 0.74 | карточки + портовые якоря | рамки | по портам (или боковой якорь, если порта нет) |
| **mid**  | 0.31–0.74 | карточки; якоря только у выделенного/под курсором | рамки | боковые якоря по геометрии (`geoSide`) |
| **far**  | zoom < 0.31 | хабы-маяки; оконечные фасуются | пилюли 44px со счётчиком | пучки «×N» между маяками/пилюлями |

Пороги — `store.zoomBand` (near ≥ 0.74, far < 0.31), смена ступени — с
гистерезисом зума, бездребезгово.

## 3. Правила фасовки устройств (`scenePlan.deviceMode`)

- `card` — устройство отрисовано карточкой (near/mid).
- `beacon` — маяк на обзоре (хабы без группы, одиночные оконечные,
  оконечные с 2+ хабами — мультихоминг не теряем).
- `folded` — фасовано:
  - на **far** состав группы (все устройства группы с пилюлей) → в пилюлю;
  - оконечное (`ap/camera/pc/pos/printer/lock/other`) с **ровно одним**
    видимым хабом (`switch/router`) → в этот хаб — на far всегда, на mid/near
    при включённом `collapseEndpoints` (прежнее поведение тумблера);
  - транзит: если хаб сам фасован в пилюлю, оконечное едет в пилюлю.

Счётчики: хаб показывает «N down» и точки по типам (HubEndpoints/
FarEndpointStrip), пилюля — `childCount` в шапке.

## 4. Правила групп (`scenePlan.groupMode`)

- `hidden` — нет устройств и подгрупп («спящие» после стратегий раскладки,
  v0.67): не рисуем пустую рамку.
- `pill` — обзор (far) или ручной коллапс: пилюля 44px со счётчиком;
  двойной клик — «нырок» (приближение к прямоугольнику группы,
  `netmap:focus-group`).
- `frame` — обычная рамка (mid/near).

## 5. Правила связей

- **near**: ребро к портовому якорю, если порт существует и якоря отрендерены
  (`exposesPortAnchors`: near | selected | hover); иначе — боковой якорь по
  геометрии направления (`geoSide`: `_top/_right/_bottom/_left`).
- **mid**: как near, но портовые якоря только у выделенного/под курсором
  (оптимизация v0.67: 2 DOM-узла на порт — до половины DOM схемы).
- **far**: индивидуальные кабели не рисуются; `scenePlan.bundles` — один пучок
  на пару видимых сущностей (маяк/пилюля) с бейджем «×N»; магистраль
  (оба конца — инфраструктура) — двойным штрихом (`BundleEdge.tsx`).
  Связи, полностью лежащие внутри одной сущности, скрыты (их показывает счётчик).
- Фильтры (кабель/VLAN/слои) уважаются и планом (`linkVisible`), и рёбрами.

## 6. Правила расположения (геометрия)

- **Стратегии** (шеврон на панели / меню «Вид»): гибрид (локация → VLAN →
  /24), только локации, только VLAN, только /24. Стратегия переорганизует ВСЮ
  карту (`takeOverUserGroups`, v0.67); «домашние» пользовательские группы
  помнятся в `device.userGroupId` и возвращаются раскладкой «без группировки».
- **Радиальная «радуга»** (v0.66): ядро в центре, хабы по орбите 380,
  оконечные дугами 110px наружу; группы — мета-узлы с сеткой внутри.
- После любой раскладки — авто fit-view (`netmap:layout-applied`).
- Раскладки детерминированы и откатываются Ctrl+Z.

## 7. Производительность (что и чем оптимизировано)

| Источник DOM/работы | Решение | Где |
|---|---|---|
| Портовые якоря (2/порт) | рендер только near/selected/hover | `ModernDeviceNode.exposesPortAnchors` |
| Карточки оконечных на far | фасовка в хабы | `scenePlan` |
| Рамки групп на far | пилюли 44px | `scenePlan` |
| Параллельные кабели на far | пучки «×N» | `scenePlan.bundles` + `BundleEdge` |
| Повторные расчёты при зуме | один чистый план в useMemo | `Canvas.scenePlan` |
| Ре-рендеры строк/точек | узкие zustand-селекторы, memo-компоненты | по всему src |

Бюджет обзора (far) на большой карте: узлы ≈ хабы + группы (десятки),
рёбра ≈ пучки (десятки) — вместо тысяч портовых якорей и сотен кабелей.

## 8. Интерактив, завязанный на фасовку

- Двойной клик по пилюле/группе — нырок в неё (fit к прямоугольнику).
- «Приблизить» в баннере обзора — полёт к центру контента.
- Ховер строки «Подключённые устройства» (v0.66) — подсветка на карте;
  ховер карточки — подсветка строки (единый `hoveredDeviceId`).
- Клик по маяку/пилюле — выбор и панель справа; двойной клик по маяку —
  крупный вид (Focus View).

## 9. Где что живёт

- `src/scenePlan.ts` — контракт сцены (правила 2–5);
- `src/Canvas.tsx` — отображение плана (узлы/рёбра/нырок);
- `src/ModernDeviceNode.tsx` — LOD карточки и портовых якорей;
- `src/BundleEdge.tsx` — пучок «×N»;
- `src/radialLayout.ts`, `src/smartLayout.ts`, `src/autoLayout.ts` — геометрия (п. 6);
- `src/layers.ts` — иерархия (принцип 2).
