# Разбор рабочей области ComfyUI — что даёт плавность и что берём в NetMap

Дата: 2026-10-05. Источники: репозиторий Comfy-Org/ComfyUI_frontend (deepwiki-обзор
архитектуры), docs.comfy.org «Nodes 2.0», блог Comfy «Try Nodes 2.0», CI-отчёты
performance-харнесса (Playwright, PR #20147), обсуждение команды на Reddit
(r/StableDiffusion, «Why is ComfyUI using LiteGraph.JS?»).

## 1. Как это устроено у них

**Классический режим (то, что все знают как «плавный ComfyUI»):**
- весь граф — **один Canvas2D** (форк litegraph.js, `src/lib/litegraph`):
  узлы, связи, виджеты — пиксели, не DOM. Ноль DOM-узлов на элемент графа;
- команда прямо говорит: «litegraph … performant because everything is
  rendered on the canvas and not in the DOM. **ReactFlow cannot render so
  many nodes at the same time**»;
- панорамирование/зум — трансформация одного канваса, hit-testing и ховер —
  вручную по геометрии (immediate mode), никаких React-ре-рендеров на кадр.

**Nodes 2.0 (декабрь 2025):** узлы переехали на Vue-компоненты (DOM) ради
богатых интеракций, но:
- связи и фон остались на канвасе (гибрид: DOM-узлы + canvas-связи,
  координаты синхронизирует TransformPane);
- в CI появился **performance-харнесс с бюджетом**: сценарии canvas-idle /
  mouse-sweep / zoom-sweep / node-drag, цели — 60 fps (avg и P5), TBT 0 ms,
  frame time 17 ms, heap ~65 MB. Каждый PR отчитывается цифрами.

## 2. Чем NetMap отличается (честно)

NetMap — React Flow: каждый узел — DOM-поддерево (карточка, пилюли, порт-
якоря), рёбра — SVG. На 100+ устройств это принципиально тяжелее канваса —
та самая причина, по которой ComfyUI когда-то ушёл с DOM-подхода.
Что у нас уже сделано против этого (и работает):
- LOD-ступени near/mid/far: карточки → маяки → пилюли (v0.57–v0.68);
- фасовка оконечных в хабы и пучки «×N» (v0.68);
- focus-first: старт с ядра + 2 кольца (v0.72);
- порт-якоря только на near/ховере — минус 40–57% DOM (v0.67);
- non-scaling-stroke, минимум лейблов (v0.69);
- узкие селекторы zustand (тик мониторинга не перерисовывает карту).

Чего у нас нет из их рецептов:
1. **Гибридного канваса** — на far-ступени мы всё ещё рисуем DOM-маяки и
   SVG-пучки; ComfyUI-плавность на больших картах даёт именно канвас.
2. **Измерений** — у них каждый PR показывает fps/TBT по сценариям; у нас
   нет ни фпс-метра, ни бюджета. «Плавность» не доказуема без цифр.
3. **Мгновенных микро-интеракций immediate-mode**: у них ховер-подсветка
   связи, превью линка при протяжке, search-палитра по двойному клику — всё
   на канвасе без задержек. У нас ховер-подсветка есть, но остального нет.

## 3. Кандидаты к переносу (по убыванию соотношения эффект/риск)

**A. FPS-метр + бюджет плавности (малый шаг, фундамент).**
Оверлей «fps / ms / узлов» (меню Вид), цель: 60 fps на idle/pan/zoom/drag
при 124+ устройствах. Без этого дальнейшие оптимизации — вслепую.

**B. Canvas-слой для far-ступени (главный «comfy-приём»).**
На зуме < 0.31 вместо DOM-маяков и SVG-пучков — один `<canvas>`: маяки,
пилюли групп, пучки и «+N» рисуются 2D-контекстом, ховер/клик — hit-testing
по геометрии. DOM остаётся для near/mid (богатые карточки — наша сила).
Это буквально архитектура ComfyUI Nodes 2.0 наоборот: у них DOM-узлы +
canvas-связи, у нас canvas-обзор + DOM-ближний план.

**C. Search-палитра (двойной клик по пустому месту / Ctrl+Space).**
Как в ComfyUI: всплывающий поиск — добавить устройство / перейти к
существующему / включить группу. Убирает походы в меню и сайдбар.

**D. Протяжка связи в пустоту = «создать и подключить».**
Как в ComfyUI: тянем порт, бросаем на пустое место — палитра выбора
устройства, связь создаётся сразу. Сейчас бросок в пустоту — ничто.

**E. Мелочи immediate-mode:** ховер-подсветка инцидентных связей на маяках
(есть только на карточках), превью-линия при протяжке (в RF есть, проверить
стиль), тост «отменено» после Ctrl+Z (есть alert-подход — заменить).

## 4. Что НЕ берём

- Полный перевод карты на Canvas2D (отказ от DOM-карточек): наши карточки —
  тултипы, статусы, «N down», «+N», порт-виды — это сила продукта; ComfyUI
  сам ушёл с чистого канваса обратно к DOM-узлам (Nodes 2.0) ради богатых
  интеракций. Гибрид — да, замена — нет.
- Их форк litegraph как зависимость: он про workflow-редактор (порты
  данных, исполнение графа), не про физическую топологию; тащить чужой
  рантайм ради одного режима отрисовки неоправданно — canvas-слой у нас
  будет свой, тонкий (у нас уже есть опыт: MiniMap, пилюли).

## 5. Метрики успеха (их формат)

| Сценарий | Цель |
|---|---|
| idle (124 устр., near) | 60 fps, TBT ≈ 0 |
| pan/zoom sweep (far, вся карта) | ≥ 50 fps сейчас → 60 после B |
| drag узла (near) | 60 fps |
| heap после 5 мин работы | ≤ ~100 MB |
